# 온기 🐾 유기동물 입양 찾기

공공데이터포털 **농림축산식품부 농림축산검역본부_국가동물보호정보시스템 구조동물 조회 서비스**(v2)를 이용해
전국 보호소의 구조동물을 찾아보는 웹앱입니다. (모바일프로그래밍실무 중간고사 과제 · 3단계 완성본)

## 전체 구조
```
[GitHub Pages: HTML/CSS/JS]  ──찜·조회수·댓글·AI글──▶  [Firebase Realtime Database]
        │  (키 없이 요청)
        ▼
[Google Apps Script 웹 앱]  ── 인증키로 호출 ──▶  [공공데이터포털 구조동물 API]
   · 키 보관 (스크립트 속성)                    ──▶  [Gemini API]
   · 일괄 조회 / 캐시                             ──▶  [구글 시트: 알림 구독자]
   · 매일 9시 트리거 ── 새 공고 ──▶ [Gmail 알림]
```

## 페이지 구성 (6페이지)
| 파일 | 내용 |
|---|---|
| `index.html` | 구조동물 목록 · 필터 · 정렬 · 페이지네이션 · ♡ 찜 |
| `match.html` | 7문항 입양 성향 테스트 · 궁합 점수 추천 · 신규 공고 메일 알림 구독 |
| `detail.html` | 동물 상세 · 공고 기간 진행률 · ✨ AI 입양 홍보글 · 찜/조회수 · 공유/QR · 응원 댓글 · 같은 보호소의 다른 아이들 |
| `map.html` | 보호소 지도 (카카오맵 · 클러스터) · 내 위치에서 가까운 순 |
| `stats.html` | 보호 현황 통계 (KPI 4개 + Chart.js 차트 5개) |
| `favorites.html` | 내 찜 (최신 상태 자동 확인) · 인기 랭킹 (찜 수 · 조회수 TOP 10) |

## 사용한 API (JSON)
기본 주소: `https://apis.data.go.kr/1543061/abandonmentPublicService_v2`

| 기능 | 오퍼레이션 | 쓰이는 곳 |
|---|---|---|
| 시도 조회 | `sido_v2` | 시도 선택, 시도별 통계 |
| 시군구 조회 | `sigungu_v2` | 시도 선택 후 시군구 목록 |
| 보호소 조회 | `shelter_v2` | 시군구 선택 후 보호소 목록 |
| 품종 조회 | `kind_v2` | 축종 선택 후 품종 목록 |
| 구조동물 조회 | `abandonmentPublic_v2` | 목록, 상세(`desertion_no`), 같은 보호소(`care_reg_no`), 통계 건수 |

## 기술 요소 (PPT 정리용)
1. **연쇄 필터**: 시도 → 시군구 → 보호소, 축종 → 품종을 API로 단계별 조회
2. **URL 상태 관리**: 필터·페이지를 주소에 저장 → 새로고침·뒤로가기·링크 공유 시 그대로 유지
3. **D-day 로직**: 공고 마감일로 `공고 D-n` / 공고 종료 후 `입양 대기 n일째` 계산·색상 구분
4. **페이지네이션**: totalCount로 전체 페이지 계산, 5개 단위 페이지 버튼
5. **정렬**: 최근 구조순 · 공고 마감 임박순 · 입양 대기 오래된 순 · 어린 순
6. **데이터 정규화**: `2024(년생)` → `약 2살`, `3(Kg)` → `3kg`, http 이미지 → https 변환
7. **오류 처리**: 인증키 오류(XML 응답)를 DOMParser로 해석해 한글 안내, 재시도 버튼
8. **캐시**: sessionStorage에 10분간 응답 저장 → 같은 요청 반복 방지
9. **경쟁 상태 방지**: 필터를 빠르게 바꿔도 마지막 요청 결과만 화면에 표시
10. **동시 요청 제한 풀**: 통계 페이지의 30여 개 요청을 4개씩 나눠 처리하고 진행률 표시
11. **통계 시각화**: Chart.js로 주별 추이·시도별·축종·나이대·처리 결과 차트
12. **샘플 데이터 모드**: 인증키가 없거나 시연 중 API 장애 시에도 화면 확인 가능
13. **반응형 UI**: 스켈레톤 로딩, 빈 결과 안내, 모바일 2열 카드

### 2단계에서 추가된 기술 요소
14. **Firebase Realtime Database**: 찜 · 조회수 · 응원 댓글을 저장하고 `on('value')`로 실시간 반영
15. **트랜잭션**: 여러 사람이 동시에 찜해도 숫자가 정확하도록 `transaction()`으로 증가/감소
16. **서버 정렬 쿼리**: `orderByChild().limitToLast(10)`로 인기 랭킹 TOP 10만 받아옴
17. **보안 규칙**: 조회수는 1씩만 증가, 댓글은 200자 이하 · 수정 불가 · 서버 시간만 허용 (`database.rules.json`)
18. **낙관적 업데이트**: ♡를 누르면 화면 먼저 바꾸고 저장은 뒤에서 처리
19. **찜 상태 추적**: 찜한 아이를 API로 다시 조회해 "새 가족을 만났어요" 등 변화 알림
20. **카카오맵 + 지오코딩**: 보호소 주소 → 좌표 변환 (실패 시 장소명 검색), 결과를 localStorage에 캐시
21. **마커 클러스터러**: 전국 보호소 마커를 묶어서 표시
22. **Geolocation + 하버사인 공식**: 내 위치에서 보호소까지 직선거리 계산 · 가까운 순 정렬
23. **공유**: 링크 복사(Clipboard API), 휴대폰 공유창(Web Share API → 카카오톡 등), QR 코드 생성
24. **대체 모드**: 키가 없으면 지도 없이 목록만, Firebase 없으면 브라우저 저장(로컬 모드)으로 동작

### 3단계에서 추가된 기술 요소
25. **GAS 프록시 서버**: 공공데이터·Gemini 키를 GAS 스크립트 속성에만 보관 → 웹페이지 소스에 키가 없음
26. **허용 목록 검증**: GAS가 허용된 API·파라미터만 전달해 다른 용도로 악용 불가
27. **일괄 조회**: 통계 페이지 30여 개 요청을 15개씩 묶어 `UrlFetchApp.fetchAll`로 병렬 처리 (호출 2번)
28. **서버 캐시**: GAS `CacheService`로 같은 요청은 10분간 재사용 (트래픽 절약)
29. **Gemini AI 소개글**: 서버가 공고 정보를 직접 조회해 프롬프트 생성 → 지어내기 금지 규칙, 모델 자동 대체(최신 → 이전 모델)
30. **AI 결과 공유 저장**: 한 번 만든 글은 Firebase에 저장해 모든 방문자가 재사용 (API 비용 절약)
31. **성향 테스트 추천 알고리즘**: 주거·외출 시간·산책·경험·나이 선호와 체중·나이·중성화·특징 기록을 점수화하고 추천 이유 표시
32. **신규 공고 알림**: 구글 시트를 구독 DB로 쓰고, 매일 오전 9시 시간 트리거가 새 공고만 골라 HTML 메일 발송
33. **중복 발송 방지**: 구독자별로 이미 보낸 유기번호를 기록, 같은 조건은 한 번만 조회
34. **동시성 제어**: 구독 저장 시 `LockService`로 동시에 저장되는 문제 방지, 해지 링크(토큰) 제공

## 3단계: GAS 서버 설정 (약 10분)
1. 구글 드라이브 > 새로 만들기 > 더보기 > **Google Apps Script** (또는 주소창에 `script.new`)
2. 프로젝트 이름을 `온기 서버`로 바꾸고, `Code.gs` 내용을 모두 지운 뒤 **`gas/Code.gs` 내용을 붙여넣고 저장**
3. 왼쪽 **⚙️ 프로젝트 설정 > 스크립트 속성 > 스크립트 속성 추가**로 3개 입력

   | 속성 | 값 |
   |---|---|
   | `SERVICE_KEY` | 공공데이터포털 일반 인증키 |
   | `GEMINI_API_KEY` | Gemini API 키 |
   | `SITE_URL` | GitHub Pages 주소 (예: `https://hwh-test.github.io/ongi/`) |

4. 편집기 상단 함수 목록에서 **`setup`** 선택 > **실행**
   - 권한 승인 창: 계정 선택 > **고급 > 온기 서버(으)로 이동(안전하지 않음)** > 허용
   - 실행 로그에 "구독자 시트 생성", "트리거 등록 완료"가 나오면 성공 (내 드라이브에 '온기 알림 구독자' 시트 생성)
5. **`testApi`** 실행 → 로그에 시도 목록 JSON이 보이면 공공데이터 키 정상
6. **`testGemini`** 실행 → 로그에 한 문장이 보이면 Gemini 키 정상
7. 오른쪽 위 **배포 > 새 배포 > 유형 선택(⚙️) > 웹 앱**
   - 실행 계정: **나** / 액세스 권한: **모든 사용자** > 배포
   - 나오는 **웹 앱 URL**(`https://script.google.com/macros/s/…/exec`) 복사
8. `js/config.js`의 `PROXY_URL`에 그 URL을 넣고, **`SERVICE_KEY`는 `''`로 비우기** (이제 키는 GAS에만 있음)

> GAS 코드를 수정했다면 **배포 > 배포 관리 > ✏️ 수정 > 버전: 새 버전 > 배포**를 해야 반영됩니다. (URL은 그대로)

## 2단계 키 설정
`js/config.js`에서 두 곳을 채웁니다.
```js
KAKAO_JS_KEY: '카카오 JavaScript 키',
FIREBASE: {   // Firebase 콘솔에서 복사한 firebaseConfig 내용으로 통째로 교체
  apiKey: '...', authDomain: '...', databaseURL: 'https://...firebasedatabase.app', projectId: '...', ...
},
```

### Firebase 보안 규칙 적용 (꼭 해주세요)
1. Firebase 콘솔 > Realtime Database > **규칙** 탭
2. 기존 내용을 모두 지우고 `database.rules.json` 파일 내용을 붙여넣기 > **게시**
3. 테스트 모드(30일 만료) 대신 이 규칙을 쓰면 기간 제한 없이 동작하고, 랭킹 정렬용 인덱스(`.indexOn`)도 함께 설정됩니다.

### 카카오 콘솔 확인 사항
- 앱 > 플랫폼 키 > JavaScript 키 > **JavaScript SDK 도메인**에 `http://127.0.0.1:5500`, `http://localhost:5500`, `https://아이디.github.io` 등록
- 지도가 회색으로만 보이면 **카카오맵 사용 설정 ON** 여부 확인

## 실행 방법
1. 공공데이터포털에서 위 API를 **활용신청** (자동승인, 반영까지 최대 1~2시간)
2. 마이페이지 > 개발계정에서 **일반 인증키(Decoding)** 복사
3. `js/config.js`의 `SERVICE_KEY: ''` 따옴표 안에 붙여넣기
4. VS Code **Live Server**로 `index.html` 열어서 확인 (파일을 더블클릭해 열면 일부 기능이 막힐 수 있어요)

## GitHub Pages 배포 (제출 전 체크)
- [ ] `config.js`의 `PROXY_URL` 입력, `SERVICE_KEY`는 비움
- [ ] Firebase 규칙에 최신 `database.rules.json` 게시 (3단계에서 `stories` 추가됨)
- [ ] 카카오 JavaScript SDK 도메인에 GitHub Pages 주소 등록
- [ ] `gas/` 폴더는 올려도 되지만 키는 절대 코드에 쓰지 않기 (스크립트 속성에만)

1. GitHub에서 새 저장소 만들기 (예: `ongi`, **Public**)
2. `Add file` > `Upload files`로 이 폴더 안의 파일·폴더를 모두 업로드 > `Commit changes`
3. `Settings` > `Pages` > Source: **Deploy from a branch**, Branch: **main / (root)** > `Save`
4. 1~2분 뒤 `https://아이디.github.io/ongi/` 접속

> 저장소가 Public이면 인증키도 공개됩니다. 3단계에서 GAS 프록시로 키를 숨길 예정입니다.

## 문제 해결
| 증상 | 원인 · 해결 |
|---|---|
| "인증키가 등록되지 않았어요" | 활용신청 직후라 반영 대기 중. 1~2시간 후 다시 시도 |
| "서버에 연결하지 못했어요" | 네트워크 문제 또는 API 일시 장애. 잠시 후 재시도 |
| 사진이 "사진 준비 중"으로 표시 | 원본 이미지가 https를 지원하지 않거나 삭제된 경우 |
| 통계가 일부만 표시 | 요청 일부 실패. 기간 버튼을 다시 눌러 재조회 |
| 찜·랭킹 페이지에 "로컬 모드" 표시 | `FIREBASE` 설정이 비었거나 `databaseURL`이 없음 |
| 찜하면 "저장하지 못했어요" | Firebase 규칙을 게시하지 않았거나 테스트 모드가 만료됨 |
| 랭킹이 "불러오지 못했어요" | 규칙에 `.indexOn`이 없음 → `database.rules.json`으로 교체 |
| 지도 대신 안내 문구만 표시 | `KAKAO_JS_KEY` 비어 있음 |
| 지도가 회색 / 콘솔에 401·403 | 카카오 콘솔의 JavaScript SDK 도메인 등록, 카카오맵 사용 설정 확인 |
| "내 위치" 버튼이 안 됨 | 브라우저 위치 권한 허용 필요 (https 또는 localhost에서만 동작) |
| "GAS 서버 응답을 읽지 못했어요" | 웹 앱 액세스 권한이 '모든 사용자'가 아님 → 배포 관리에서 수정 |
| "GAS 스크립트 속성에 …가 없어요" | 3번 단계의 속성 이름 오타 확인 (대문자·밑줄) |
| AI 소개글 "사용 가능한 Gemini 모델을 찾지 못했어요" | 스크립트 속성 `GEMINI_MODEL`에 AI Studio에서 보이는 모델 이름 입력 |
| 알림 구독 시 "setup()을 먼저 실행" | 4번 단계 `setup` 실행 |
| 수정한 GAS 코드가 반영 안 됨 | 배포 관리에서 **새 버전**으로 다시 배포 |
